# Badminton AI Coach — 상세 설계 및 첫 번째 버전(V1) 개발 명세서

- 문서 버전: 1.0
- 작성 기준일: 2026-10-18
- 제안 프로젝트 경로: `D:\stockproj\badminton_pose`
- 최초 대상 환경: Windows 10, Python 3.12, PySide6
- 목표: **촬영된 배드민턴 동영상에서 관절 움직임을 분석하고, 측정 근거가 있는 교정 피드백을 자동 생성하는 로컬 데스크톱 프로그램**

## 1. 목표와 개발 원칙

사용자가 영상 파일을 불러와 분석 구간과 주로 사용하는 손을 지정하면, 프로그램은 프레임별 자세를 추정하고 측정 가능한 지표를 계산한 뒤 코칭 피드백과 근거 프레임을 제시한다. 인터넷 연결 없이 로컬에서 영상과 분석 결과를 관리한다.

**핵심 원칙**
1. AI가 관측한 수치와 배드민턴 코칭 의견을 분리한다.
2. 추정이 불확실한 항목은 '판정 불가'로 표시한다.
3. 데이터가 뒷받침되지 않는 임팩트 속도, 라켓 각도, 셔틀 방향, 부상 위험도는 추측하여 점수화하지 않는다.
4. 기존 기능·UI·로그를 보존하고 필요한 부분만 증분 수정한다.
5. Python 파일 맨 위에는 해당 파일의 기능과 프로그램 내 역할을 충분히 설명하는 주석을 둔다.
6. UI·분석·저장을 분리하여 Windows/Linux 모두 확장할 수 있게 한다.

## 2. 기능 범위

### V1 필수 기능
- 파일 선택: MP4 우선, OpenCV에서 지원하는 기타 동영상 포맷은 테스트 후 허용
- 영상 재생: 재생/정지/일시정지, 탐색 슬라이더, 이전/다음 프레임, 재생 속도 0.25/0.5/1.0배
- 분석 구간: 시작/끝 지점 지정. 초기에는 한 구간을 대상으로 분석
- 설정: 주로 사용하는 손(오른손/왼손), 촬영 시점(정면/측면/사선), 분석 동작 '포핸드 오버헤드 연습 스윙'
- 자세 인식: MediaPipe Pose Landmarker의 VIDEO 모드로 33개 신체 랜드마크 추적
- 시각화: 원본 영상 위 골격·랜드마크·프레임 시간 표시, 오버레이 켜기/끄기
- 측정: 팔꿈치 굴곡각, 어깨-팔꿈치-손목의 상대 위치, 양어깨/골반의 화면 내 방향, 몸통 측면 기울기 등 촬영 시점상 측정 가능한 항목
- 코칭: 사전에 정의한 소수의 규칙에 따라 '관측 사실 → 개선 후보 → 다음 촬영에서 확인할 행동' 형식의 피드백 제공
- 품질 관리: 랜드마크 가림·검출 누락·불명확한 촬영 각도에 따라 신뢰도 표시 및 판정 보류
- 저장: 원본 영상 경로, 설정, 랜드마크 캐시, 지표, 코칭 결과, 앱 로그 저장
- 내보내기: 분석 요약 CSV/JSON 및 근거 프레임 PNG
- 분석 작업: 진행률·취소·오류 안내. GUI가 멈추지 않도록 작업 스레드 분리

### V1 제외 기능(후속 확장)
- 경기 중 다인원 인식과 특정 선수의 완전 자동 추적
- 스매시/클리어/드롭의 영상 기반 자동 분류
- 셔틀콕·라켓의 정확한 추적과 타격 순간 자동 확정
- 코치 자세의 정확한 자동 채점, 100점 만점의 종합점수
- 클라우드 LLM 서비스 연동, 모바일 앱, 실시간 카메라 코칭
- 임상적 부상 위험 예측, 무릎/어깨 질환 진단

## 3. V1 분석 동작과 영상 조건

**대상 동작:** 포핸드 오버헤드 스트로크의 연습 동작. 처음부터 '정확한 스매시'나 '정확한 클리어'의 자동 판별을 시도하지 않는다.

**권장 촬영:** 선수 한 명이 머리부터 발까지 프레임 안에 나오도록 카메라를 고정한다. 가능하면 60fps 원본, 충분한 조명, 가로 촬영, 선수와 배경의 색 대비 확보. 정면·측면 영상을 별도로 촬영하면 관찰할 수 있는 내용이 늘어난다. 스마트폰 슬로모션 영상의 실제 재생 타임스탬프는 파일별로 확인한다.

**V1 현실적 제한:** 손목 스냅과 라켓 헤드 각도는 Pose Landmarker만으로 판정하기 어렵다. 단일 카메라의 추정 3D 관절 좌표는 정밀 모션캡처가 아니므로 절대적인 3D 관절각을 확정적으로 표현하지 않는다.

## 4. 처리 아키텍처

```text
[PySide6 UI / 메인 스레드]
    │  영상 선택 / 구간 설정 / 분석 시작
    ▼
[VideoController]
    │  메타데이터, 탐색, 프레임 읽기
    ▼
[AnalysisWorker / QThread]
    ├─ OpenCV Decoder → RGB 프레임 + 타임스탬프
    ├─ PoseEngine → 33개 랜드마크, visibility/presence
    ├─ QualityGate → 검출 품질/관측 가능성 평가
    ├─ MetricEngine → 각도, 상대 높이, 시계열 변화
    └─ CoachingEngine → 설명 가능한 코칭 규칙
    │
    ├──> [SQLite 메타데이터 + NPZ 관절 데이터 캐시]
    └──> [Qt Signal] → UI 영상 오버레이 / 차트 / 코칭 카드
```

- 무거운 영상 분석은 UI 메인 스레드에서 실행하지 않는다.
- MediaPipe `VIDEO` 모드는 **프레임별로 단조 증가하는 밀리초 타임스탬프**를 전달한다. 원본 타임스탬프가 부정확할 때는 파일 FPS·프레임 인덱스로 대체하되 원본과 보정값을 기록한다.
- OpenCV BGR 프레임을 RGB로 변환해 MediaPipe에 전달한다.
- 동영상 재생과 오프라인 분석은 분리한다. 재생 중 매 프레임 AI 추론을 다시 실행하지 않고 저장된 결과를 시간 기준으로 겹쳐 보여준다.
- 분석 캐시는 영상 식별정보·구간·모델 버전·규칙 버전·설정에 따라 무효화한다.
- CPU 우선 구현 후 필요할 때 GPU/모델 가속을 검토한다. V1은 PyTorch에 의존하지 않는다.

## 6. 관절 지표 및 코칭 엔진 상세

### 지표
- **팔꿈치 굴곡각:** 어깨–팔꿈치–손목 세 점이 이루는 각도. 관찰 가능한 프레임에서만 계산.
- **손목 상대 높이:** 손목과 어깨의 화면상 수직 거리/몸통 크기 정규화 값. 카메라가 심하게 기울어진 경우 제한.
- **몸통 기울기:** 양어깨 중점과 양골반 중점을 이은 선의 이미지 내 기울기. 실제 허리 회전각과 혼동하지 않는다.
- **상지 시계열:** 팔꿈치 굴곡각·손목 높이 변화량을 시간 흐름에 따라 그래프로 시각화.
- **자세 검출 커버리지:** 선택 구간에서 주요 관절을 충분히 추적한 프레임 비율.

### 코칭 생성 절차
1. 프레임별 랜드마크 품질을 평가한다.
2. 허용된 관찰 지표만 시간에 따라 계산한다.
3. 사용자가 표시한 구간/선택적 핵심 프레임을 기준으로 비교한다.
4. 최초에는 **정보성 규칙**만 적용한다. 예: '손목이 어깨보다 높아진 시점이 확인됩니다', '백스윙 구간에서 팔꿈치 각도가 크게 변합니다'.
5. 각도·타이밍의 **좋고 나쁨 판정은 촬영 조건, 지도자 검토 및 테스트 영상으로 임계값을 검증한 다음** 단계적으로 추가한다.
6. 코칭 카드에 근거값·타임스탬프·품질 등급·다음 촬영에서 확인할 행동을 함께 표시한다.

**예시 출력(가상의 측정치로, 실제 분석 결과가 아님):**

- 관찰: `2.10초 → 2.43초 구간에서 오른팔 팔꿈치 굴곡각이 106°에서 154°로 변화했습니다.`
- 해석: `전방 스윙에서 팔이 펴지는 움직임이 관찰됩니다. 이 변화만으로 타격 기술의 우수성을 판정할 수는 없습니다.`
- 연습 체크: `같은 카메라 위치에서 3회 촬영하고 팔꿈치 변화 시점의 일관성을 비교해 보세요.`
- 신뢰도: `중간(손목 가림 프레임 일부 존재)`

**판정 보류 사례:** 손목이 라켓/몸에 가려짐, 대상 선수가 일부 프레임에서 화면 밖으로 이동함, 복수 선수로 인해 추적 대상이 바뀜, 촬영 시점상 비교가 불가능함.

## 7. 저장 및 데이터 모델

```text
videos
  id, source_path, source_size, source_mtime, fps, width, height,
  duration_ms, imported_at
analysis_sessions
  id, video_id, dominant_hand, camera_view, motion_type,
  start_ms, end_ms, model_version, rules_version, created_at, status
metrics
  id, session_id, metric_code, summary_json, quality_json
coaching_feedback
  id, session_id, rule_code, start_ms, end_ms, evidence_json,
  message, recommendation, confidence, status
```

- 매 프레임의 33개 랜드마크는 `data/cache/*.npz`에 저장. 타임스탬프 및 visibility/presence 포함.
- SQLite는 검색 및 재실행에 필요한 메타데이터와 요약 결과 위주로 유지.
- 설정은 `config/settings.json`, 로그는 `logs/app.log`, 사용자용 출력물은 `output/`.
- 영상 및 개인 훈련 자료는 기본적으로 외부로 전송하지 않는다.

## 12. 개발 환경 구성(Windows PowerShell)

```powershell
mkdir D:\stockproj\badminton_pose
cd D:\stockproj\badminton_pose
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install PySide6 opencv-python mediapipe numpy pytest
.\.venv\Scripts\python.exe -c "import cv2, mediapipe, numpy, PySide6; print('dependencies OK')"
git init
code .
```

위 명령은 Python 3.12가 설치되어 있고 VS Code의 `code` 명령이 등록되어 있다는 전제다. 공식 안내에 따르면 MediaPipe Pose Landmarker 사용 시 호환되는 `.task` 모델 파일을 별도로 받아 지정해야 한다. 라이브러리 버전은 최초 실행 검증 후 `requirements.txt`로 고정한다. Windows에서는 Docker 없이 로컬 `venv`로 개발한다.
