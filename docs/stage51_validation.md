## 변경한 실행 조건

코칭 생성 실행과 기술 평가 가능성을 분리한다. 실행 조건은 현재 영상/원본 시간축/유효한 관절 캐시,
선택 선수·측정, 라켓 손, 이벤트, 현재 선수 연결, 유효한 선택 이벤트/규칙/저장 연결, 작업 종료다.
미검토 스윙이나 낮은 품질에서도 실제 관측/평가 보류 사유를 생성할 수 있으나 기술 판단을 통과시킨 것은 아니다.
기술 품질 판정은 기존 `assess_quality()`와 코칭 엔진을 그대로 사용한다.

상태 표시는 영상 → 관절 → 선수 → 스윙 검출 → 스윙 검토 → 코칭 → 결과·저장 7단계다.
완료/진행 중/사용자 확인 필요/분석 불가/재분석 필요/오류를 표시하고 전체 완료 수를 별도로 보여준다.
캐시/선수 재검증 필요 상태도 구체적인 해결 작업과 함께 표시한다.
작업 7/7 완료는 결과 생성·저장 완료이지 기술 평가 성공이 아니다.

`DiagnosticItem`은 내부 원인 코드와 제목/상태/이유/해결 동작/차단 여부를 분리한다.
주요 원인은 `VIDEO_MISSING`, `TIMELINE_PENDING`, `POSE_MISSING`, `POSE_SOURCE_CHANGED`,
`PLAYER_MISSING`, `MEASUREMENTS_PENDING`, `HAND_MISSING`, `SWINGS_MISSING`,
`PLAYER_LINK_REQUIRED`, `MOTION_INPUT_CHANGED`, `SWING_NOT_SELECTED`, `SWING_REVIEW_REQUIRED`,
`RULES_INVALID`, `COACH_STORE_ERROR`, `QUALITY_DEFERRED`, `ANALYSIS_BUSY`다.
최근 코칭·스윙 작업 오류는 이전 결과와 구분해 표시하며 실패를 완료로 처리하지 않는다.

## UI와 해결 작업

- 상단 통합 상태·전체 진행·캐시 상태와 `분석 상태 확인`, `다음 단계 실행`, `검토 완료` 추가.
- 비활성 코칭 버튼 옆의 `실행 조건 확인`은 항상 누를 수 있다.
- 진단 창은 항목별 이유/해결 방법, 실제 원본·모델 검사와 선택 스윙의 규칙 7개 적용/보류 근거를 표시한다.
- 다음 작업은 기존 영상 선택/관절 분석/선수 선택/라켓 손/스윙 검출/스윙 보기/코칭/결과 동작을 재사용한다.
  완료된 관절 추론을 무조건 다시 실행하지 않으며 사람의 판단을 자동 승인하지 않는다.
- 새 검출의 첫 후보를 선택하지만 스윙·단계 검토는 승인하지 않는다.
- 종료된 작업을 목록에서 제거한 직후 코칭·진단도 갱신하여 별도 재생/탐색 없이 버튼을 활성화한다.
- 결과 없는 패널은 65px 최소 높이의 간결한 안내로 바꾸고 세부 탭을 숨긴다.
  결과가 생기면 기존 관찰/측정/반복 비교 탭을 복원한다. 비교·검토 설정은 필요할 때 펼친다.
- QSplitter의 코칭/스윙 펼침 높이를 별도 저장하고 다른 패널 크기를 3개 값으로 덮어쓰지 않는다.
- 분석 요약에 선택 스윙 범위, 상태, 추적 관측 수, 단계 상태를 표시한다. 전체 보류 사유는 진단/상세/툴팁에 유지한다.
- 서로 폭이 다른 그래프/타임라인은 픽셀 위치 정렬 대신 같은 원본 PTS 초 범위를 양방향 연결한다.
  기존 그래프 범례·곡선·탐색·A/B 통계를 유지한다.

## 저장 선수 연결과 자료 보호

`AnalysisCache.run_id`와 선택적 `MotionResult.provenance`에 관절 실행 ID, 캐시 지문,
프레임·관절·선택·측정·시간축의 입력 지문을 기록한다. 구버전 JSON은 출처 빈 값으로 읽는다.
기존 motion/coaching 스키마를 삭제하거나 초기화하지 않는다.

저장 선수 연결은 별도 작업 스레드에서 다음을 검증한다.

1. 현재 파일과 원본 PTS 시간축의 영상 경로·크기·mtime 일치.
2. 영상/모델/MediaPipe/분석 설정을 포함하는 실제 `cache_key()` 일치.
3. 저장 영상/라켓 손/선수 문맥과 현재 선택 기준 프레임·몸통 위치 일치.
4. 자동 원본 및 현재 이벤트의 모든 프레임에서 현재 선택 세션·측정 세션/시각 일치.
5. 몸통 검출 및 하나의 연속 추적 구간. 누락·다른 선수·시간 단절은 연결 거부.

검증을 통과해도 기본 No인 확인 창에서 동일 선수임을 사용자가 직접 확인해야 한다.
선수 검출 순번을 신원으로 사용하지 않는다. 선택 기준/촬영 영상이 다른 대상을 강제로 연결할 수 없다.
거부 시 원본을 유지하고 재선택/현재 선수의 새 검출로 안내한다. 손/검출 설정 변경은
연결 승인만으로 해결되지 않으므로 영향받는 스윙 갱신을 안내한다.

승인 후에도 경계·단계·라벨·이벤트 ID와 수동 출처는 보존하고 현재 캐시에서 수치/피크/지표를 재계산한다.
세션 ID는 현재 추적 구간에 갱신하고 이전 문서는 기존 MotionStore 이력에 보존한다.
이 승인으로 스윙 검토나 품질 검사를 대신하지 않는다. 코칭 메모와 사용자 검토는 지우지 않으며
관련 입력 지문이 달라지면 기존 결과는 재계산/재확인 대상으로 남는다.
수동 수정본의 자동 재검출 교체는 기존 확인 대화상자를 유지한다.

캐시는 재사용 가능/재검증 필요/재계산 필요/현재 결과와 호환되지 않음으로 구분한다.
A/B만 바뀐 경우 기존 스윙과 코칭 결과는 재사용한다. 라켓 손·검출 설정·선수·관절 실행·이벤트·단계·규칙
변경은 각각 영향을 표시한다. 원본 파일 변경은 다시 불러오기, 모델/분석 설정 변경은 관절 캐시 갱신으로 안내한다.
무거운 파일 해시·특징/규칙 검사는 QThread에서 수행하며 현재 입력이 바뀐 늦은 결과는 버린다.

### 실제 문제 영상 Windows 통합 검증

`run_readiness_smoke.py`는 현재 사용자 문제 영상과 공식 MediaPipe 모델을 사용한다.
`output/readiness_smoke/<실행시각>`에 설정/스윙/코칭 복사본을 격리한다.
사용자 원본은 읽기만 하며 검증 전후 SHA-256으로 변하지 않았음을 확인한다.
테스트의 선수 연결/검토 승인은 명시적인 테스트 동작이며 실제 사용자의 선수·스포츠 정답 확인이 아니다.
네이티브 포인터 주입 대신 활성화된 버튼의 정상 Qt `clicked` 경로와 선택 동작을 사용한다.

확인한 경로:

영상 불러오기 → 실제 관절 175/175 → 실제 선수 선택 → 측정 가능 142 →
과거 연결 차단 재현 → 검증+테스트 확인 승인 → 저장 경계 보존 →
전체 범위 스윙 후보 3개 → 스윙 보기/검토 → 코칭 버튼 활성화 확인 → 버튼 클릭 → 결과 표시/저장.

선택 이벤트의 유효 관측은 42/42이고 스윙 검토를 완료해도 단계 일부가 불확실해
`COACHING_DEFERRED`다. 이는 실행 실패가 아니라 근거를 보존한 평가 보류 결과다.
관찰 메시지와 보류 사유가 실제 표시됐으며 작업 상태는 결과 생성·저장 완료로 구분됐다.
최종 통합 실행은 **33.73초, 오류 없음, passed=true**, UI 타이머 486회 응답이다.
코칭 보고서 1개에 규칙 결과 7개가 생성됐고 모든 정상 작업 단계가 결과·저장까지 도달했다.

추가로 실제 근거 프레임/그래프·타임라인 PTS 일치, A/B 적용 뒤 기존 코칭 캐시 재사용과
관절 실행 ID 불변, 규칙 7개 진단, JSON/CSV 출력, 사용자 원본 파일 불변을 확인한다.
화면 크기는 Qt 논리 크기 1280×720 및 1920×1080이다. Windows 배율에 따라 PNG 물리 크기는 다르다.
1280×720에서 영상은 1262×180 영역에 원본 비율로 표시되며 코칭 패널을 접으면 더 넓어진다.
다른 DPI/실제 모니터 모드 전체 조합의 검증을 주장하지 않는다.

## 남은 제한 사항

선수 문맥은 영구적인 신원 ID나 얼굴 인식이 아니다. 동일 영상/기준 몸통/추적 검사와 사용자 확인이 필요하다.
구버전 파일에는 원래 관절 실행 ID가 없으므로 이를 소급해서 만들어 원래 분석과 같다고 주장하지 않는다.
원래 기준 프레임을 다르게 선택하거나 자동 원본/현재 이벤트 중 일부가 추적 불가이면 연결을 거부할 수 있다.
이 경우 원래 선수 재선택 또는 수동 자료를 보호한 새 검출이 필요하다.
미관측 단계를 생성하거나 UNKNOWN을 승인만으로 정상 단계로 바꾸지 않는다.
실제 기술 판단/지도 효과/다양한 촬영 조건에서의 정확도는 이 검증으로 입증되지 않았다.
저해상도에서 모든 보조 패널을 동시에 펼치면 영상 영역이 줄어들므로 패널 접기/크기 조절을 사용한다.
전문가 검토와 다양한 영상·DPI 환경의 추가 회귀 검증이 다음 개선 과제다.
